## Cost categories

| Category | What to include |
|---|---|
| Subscription or licence | Core product, modules, users and entities, for every year of the term |
| Implementation | Partner services: design, configuration, migration, testing, training |
| Integrations | Build and maintenance of links to CRM, payroll, banking, ecommerce |
| Add-ons | Marketplace subscriptions the solution depends on |
| Support | Partner support contract after go-live |
| Hosting | Only if you run the system yourself or in private hosting |
| Upgrades | Effort to adopt new releases |
| Internal time | Your team's time on the project and on running the system |

## Costs to check

- Renewal increases after the first contract term.
- Add-ons that the demo used but the proposal does not price.
- Integration maintenance when a connected system changes.
- Backfilling the day jobs of people seconded to the project.
- A second implementation if the first choice is outgrown within five years.

## A worked example (illustrative)

The figures below are invented to show the method, not to indicate prices. Two options for the same scope:

| | Option A | Option B |
|---|---|---|
| Year-one implementation | 100 | 70 |
| Annual subscription | 50 | 45 |
| Add-ons each year | 5 | 20 |
| Support each year | 10 | 10 |
| **Five-year total** | **425** | **445** |

Option B is cheaper in year one and more expensive over five years, because it relies on more add-ons. This is the pattern a five-year view is designed to catch.
